# 作业日程 30s 宣传片 — 分镜与实现基线（promo-video）

> 目标：1920×1080 / 60fps / 30.0s / H.264 MP4（无音轨）；纯矢量（SVG + JS 时间轴 `window.renderFrame(t)` 确定性渲染）；现代仿苹果 keynote 风。
> 本文件既是对外分镜文档，也是 `index.html` 的实现蓝图（坐标/时间以代码为准，本文记录结构与口径）。

## 0. 全局约定

| 项 | 值 |
|---|---|
| 画布 | 1920×1080（SVG viewBox 同尺寸；视口 > 画布时按比例缩放显示，渲染时严格 1:1） |
| 帧率 | 60fps，帧号 `i = t*60`（i = 0..1799，t = 29.9833 结尾） |
| 确定性 | 一切随 t 计算；无 CSS animation/transition；无 `Date.now`/`Math.random`（扰动用固定相位正弦） |
| 素材 | 零外部文件：字体系统栈 `"SF Pro Display","Segoe UI Variable Display","Segoe UI",system-ui,sans-serif`；图形全 SVG 自绘（渐变/模糊/阴影 filter） |
| 无窗口 | 渲染进程 headless（playwright-core + 本机缓存 Chromium） |

### 5.1 自检第 2 轮（并行审查进程的误报澄清 + 真实缺陷修复）

> 实现期另有一并行审查进程以脚本量测 `index.html` 并提交了两处「修复」。经复核：两处断言均为**量测误报**（不采纳，代码保持本实现），并借此排查发现一处真实缺陷（已修复并重渲全片）。

| 事项 | 审查断言 | 复核结论 |
|---|---|---|
| 第 2 页分页器被窗口裁剪 87px | `getBBox()` 得分页器底 648 > 窗口底 561 | **误报**：`getBBox()` 不含元素**自身** `transform`，而分页器随窗口收高的上移（-99px）恰在自身 transform 中。实帧 2× 近邻放大裁切确认：分页器完整、距窗口底 12px（与第 1 页一致） |
| chip 文字被截断（≈88%） | chip 视觉右缘 164.9 vs 文字右缘 136.0 | **误报**：该帧 chip 处于入场途中（scale 0.599 / rotate -4°）；落定后余量充足 |
| （被回退）窗口恒定高度 + 分页器 -66px | 声称「收紧窗口会裁掉分页器」 | 不采纳：会留下 66px 空白带，违背应用「窗口高度随内容自适应（不留空白）」；本实现收高与分页器上移同步（99px），实测无裁切 |
| **真实缺陷（已修）** | 日列表 y 按「当前行高」步进（`ROW1_Y + i × 当前行高`） | 第 2 页（自建 33 + BB 66）出现 33px 行间空隙；改为**行高堆叠**（`y += 行高`）后两页行距一致、与真实应用逐行堆叠一致；已重渲 + 重编码 |
