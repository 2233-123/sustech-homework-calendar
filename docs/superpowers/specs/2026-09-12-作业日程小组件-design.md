---

## 1. 背景与目标

学生需要一个常驻桌面的轻型工具，把「课业截止」与「个人安排」统一到同一个日历视图里，并在临近时主动提醒，避免错过 Blackboard 上的作业 deadline。

**一句话目标**：一个无边框的 Windows 桌面日历小组件 —— 本地登录 SUSTech CAS → 自动拉取 Blackboard 作业 → 以日历为基底呈现 → 用户可自建日程并设置预警时间 → 到点弹窗提醒。

---

## 2. 范围

### 2.1 范围内（In Scope）
- 单用户、单账号（SUSTech）
- 本地 CAS 登录 + Windows DPAPI 加密凭据 + 启动静默自动登录
- Blackboard 作业自动拉取（**只读**）+ 定时刷新
- 自建日程的增 / 删 / 改
- 每个日程可设置预警时间，到点弹窗提醒
- 无边框悬浮日历 UI（月视图）+ 系统托盘常驻

### 2.2 非目标（Out of Scope）
- 多账号 / 多用户
- 向 Blackboard 写回（提交作业、修改内容）
- 移动端 / 公网部署 / 浏览器远程访问
- 课程公告、成绩、课表、资料下载等其它 BB 数据（列为后续可扩展项）
- 商用（参考项目许可证为 PolyForm Noncommercial 1.0.0，个人自用合规）

## 4. 关键调研结论与约束

以下结论来自对 `sustech_survival` 源码的调研，是实现必须遵守的前提。

### 4.1 CAS 登录机制
- 纯 `requests` **三步流程**，无需浏览器自动化：
  1. `GET https://cas.sustech.edu.cn/cas/login?service=<URL编码的SERVICE_URL>` → 正则提取隐藏字段 `execution`。
  2. `POST` 同一 URL，表单字段：`username`、`password`、`execution`、`_eventId=submit`、`submit=提交`；**禁止跟随重定向**（`allow_redirects=False`），期望 302/303，从 `Location` 取带 `ticket` 的跳转地址。
  3. `GET` 该 ticket 地址并**跟随重定向** → 从 cookie jar 收集全部 cookie。
- Blackboard 的 `SERVICE_URL = https://bb.sustech.edu.cn/webapps/bb-sso-BBLEARN/index.jsp`。
- ⚠️ **不能用 Playwright / 浏览器自动化登录**：CAS 有隐藏 reCAPTCHA，会静默拦截。
- 认证失败判定：`Location` 仍指向 `cas.sustech.edu.cn` 且不含 `ticket`。
- 默认超时 30s、重试 2 次。

### 4.2 Blackboard 接口
- **Base**：`https://bb.sustech.edu.cn`
- **鉴权模型**：CAS cookie 注入 `requests.Session`（cookie domain = `.bb.sustech.edu.cn`）+ Chrome UA。**无需 OAuth token / API Key**。
- **会话失效判定**：HTTP `401` → 自动重登一次。
- 关键接口见「附录 A」。
- 作业截止时间来自 `gradebook/columns` 的 `grading.due`（ISO 8601 UTC），提交状态来自 `.../attempts`。

### 4.3 会话模型
- 参考项目**仅内存保存会话**，TTL **25 分钟**，单例；每次进程启动需重新登录（仅 2–3 个请求，开销极小）。
- 参考项目**不持久化会话 cookie 到磁盘**——本设计沿用该安全实践。

### 4.4 凭据存储先例
- 参考项目 Python 层用**明文文件** `~/.sustech_survival/credentials.txt`；其 Electron 层改用 **OS keychain / Windows DPAPI**（`safeStorage`）。
- 本设计采用 DPAPI，且由 **Python 层独占**（见 §5 关键决策）。

### 4.5 必须处理的约束
| 约束 | 影响 | 应对 |
|---|---|---|
| ⚠️ 校外网络直连失败（off-campus trap） | 不在校园网/VPN 时接口不可达 | 检测网络错误，显示「可能不在校园网/VPN」提示 + 展示缓存并标注时间 |
| ⚠️ 学期 ID 硬编码（参考项目为 `_57_1`） | 换学期后拉取为空 | 动态探测学期，见 §6.2 |
| 许可证 PolyForm Noncommercial | 不可商用 | 仅个人使用 |

## 5. 总体架构

```
┌────────────────────────────────────────────────┐
│ Electron 外壳（Node 主进程）                     │
│  · 无边框 / 透明 / 置顶 / 隐藏任务栏 窗口          │
│  · 托盘图标 · 开机自启 · 拉起并守护后端进程         │
│  · 可选：系统原生通知                             │
└───────────────┬────────────────────────────────┘
                │ 加载 http://127.0.0.1:<随机端口>/
                │ HTTP(REST) + SSE(推送)
┌───────────────▼────────────────────────────────┐
│ Python 后端（仅监听 127.0.0.1 的本地服务）        │
│  · 认证模块：CAS 登录 + DPAPI 凭据库              │
│  · 同步模块：Blackboard 作业拉取 + 去重 / 缓存     │
│  · 数据层：SQLite                               │
│  · 调度模块：提醒后台线程 + SSE 推送               │
│  · 静态托管：前端页面                            │
└───────────────┬────────────────────────────────┘
                │
         ┌──────▼───────┐
         │ Web 前端      │  HTML / CSS / JS（Vite 打包）
         │ 日历 + 提醒气泡 │
         └──────────────┘
```

### 5.1 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 外壳 | **Electron**（默认） | 透明无边框窗口、托盘、通知均成熟；参考项目亦用 Electron。备选 Tauri（~10MB，但需 Rust 工具链） |
| 后端 | Python 3.10+ / Flask | 直接复用参考项目的 CAS/BB 逻辑；Flask 流式响应即可实现 SSE |
| HTTP 客户端 | `requests` | 与参考项目一致，CAS cookie 会话处理现成 |
| 凭据加密 | Windows DPAPI（`win32crypt`，备选纯 `ctypes` 调 `crypt32.dll`） | 系统级加密，仅当前用户可解密，无需自管密钥 |
| 数据库 | SQLite（Python 标准库） | 零依赖、单文件、可查询 |
| 前端 | HTML / CSS / JS + Vite | 视觉表现力强；无需重框架 |
| 提醒推送 | SSE（Server-Sent Events） | 单向推送，简单可靠；前端需断线重连 |
| 打包 | PyInstaller（后端）+ electron-builder（外壳） | 成熟组合 |

### 5.2 三个关键决策

1. **后端即应用**：Python 后端托管前端页面并提供 API，Electron 只是「无边框窗口壳」。好处是**前端可直接在浏览器里开发调试**（打开 `http://127.0.0.1:<port>`），UI 迭代与自动化测试都不依赖 Electron。
2. **凭据归 Python 管**：Python 直接用 DPAPI 加解密，**不跨进程传递密码**。参考项目恰好在「Electron 保存凭据 → 交给 Python」这一步存在缺口，本设计绕开它，令凭据流自洽、可单测。
3. **提醒用 SSE**：调度命中 → 后端推事件 → 前端弹气泡。后端是调度唯一真相源，避免 Node/Python 双重调度。

## 6. 模块设计

### 6.1 认证模块（`auth`）

- **职责**：CAS 登录、凭据加密存取、会话保活、登录态上报。
- **内部接口**：
  - `login(sid, password) -> Session`：执行 CAS 三步，成功返回 cookie 会话。
  - `ensure_session() -> Session`：有会话且未过期则复用；401 或过期则用已存凭据自动重登。
  - `save_credentials(sid, password)` / `load_credentials() -> (sid, password) | None` / `clear_credentials()`：DPAPI 加解密读写 `credentials.bin`。
  - `logout()`：清空内存会话（可选同时清除已存凭据）。
  - `get_login_state() -> "ok" | "need_login" | "failed"`。
- **逻辑要点**：
  - 凭据文件：`%APPDATA%\作业日程\credentials.bin`，DPAPI 加密（可附应用熵值）。
  - 会话：内存字典，TTL 25 分钟，进程内单例。
  - 重登：任何 BB 请求返回 401 → `ensure_session()` 触发一次自动重登；失败则置 `failed`。
- **依赖**：`requests`、`win32crypt`（或 ctypes）。

### 6.2 Blackboard 同步模块（`sync`）

- **职责**：拉取作业、归一化、去重、缓存、学期识别。
- **内部接口**：
  - `sync_now() -> SyncResult`：全量同步，写库，返回新增/更新计数。
  - `get_assignments(from, to)`：从缓存读取区间作业。
  - `detect_current_term() -> term_id | None`：学期识别。
- **拉取流程**：
  1. `GET users/me` → `uid`
  2. `GET users/{uid}/courses`（可选 `?termId=`）→ 在修课程列表
  3. 逐课 `GET courses/{bid}` → 课程名
  4. 逐课 `GET courses/{bid}/gradebook/columns?_fields=id,name,contentId,score,grading` → 过滤 `grading.type == "Attempts"` → 得到作业名 + `due`
  5. 逐作业 `GET .../columns/{col_id}/attempts` → 提交状态 / 分数 / 反馈
- **学期识别策略**（开放问题，见 §14）：优先**不带 termId** 查询全部 enrollment；若必须提供 termId，则从课程列表或设置项动态探测/缓存，绝不硬编码。
- **去重键**：`(course_id, content_id)`。
- **时区归一**：BB 的 `due` 为 UTC ISO 8601（如 `2026-03-25T15:59:00.000Z`），入库前统一转本地时间。
- **容错**：单课程失败不影响其它课程，记录错误日志；整次同步失败的保留旧缓存。
- **依赖**：复用/移植参考项目 `bb` 模块逻辑（`ddl.py`、`courses.py`、`query.py`、`items.py`）。

### 6.3 数据层（SQLite）

- **文件**：`%APPDATA%\作业日程\data.db`
- **表结构**：见 §7。
- 所有写操作串行化（单连接 + 锁），避免调度线程与请求线程并发写冲突。

### 6.4 提醒调度模块（`reminder`）

- **职责**：计算每个日程 / 作业的提醒时刻，到点触发推送。
- **逻辑**：
  - 后台线程每 **30 秒** tick。
  - 生成候选提醒：
    - 自建日程：触发时刻 = `schedule.start_at - remind_before`；
    - BB 作业：触发时刻 = `assignment.due_at - offset`（offset 取全局规则各项）。
  - 对每个「触发时刻 ≤ now」的候选，若 `reminder_log` 中不存在 `(kind, ref_id, offset_sec)` 记录，则写入记录并通过 SSE 推送 `remind` 事件；否则跳过（防重复）。
  - **补检查**：启动及系统休眠唤醒后，对触发时刻已过、但事件发生在 **24 小时内** 且尚未推送过的候选补发（避免漏提醒）。
- **预警规则**：
  - **自建日程**：每项各自设定 `remind_before`（不提醒 / 提前 5 分钟 / 15 分钟 / 30 分钟 / 1 小时 / 1 天 / 自定义）。
  - **BB 作业**：采用**全局默认规则**（默认「截止前 1 天 + 前 2 小时」，可配置、可关闭），不逐项设置。
- **范围说明**：每个日程先支持**单个**预警时间；「多个预警时间」为非目标，未来可扩展为关联表。

### 6.5 后端 API（REST + SSE）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/state` | 登录态、同步中、上次同步时间、是否疑似离线 |
| POST | `/api/auth/login` | `{sid, password, remember}` 登录并（可选）加密保存 |
| POST | `/api/auth/logout` | 退出登录（可选清除凭据） |
| POST | `/api/sync` | 立即同步 |
| GET | `/api/calendar?year=&month=` | 该月事件 = 自建日程 + BB 作业 |
| GET | `/api/day?date=` | 当日明细 |
| POST | `/api/schedule` | 新建日程 |
| PUT | `/api/schedule/{id}` | 修改日程 |
| DELETE | `/api/schedule/{id}` | 删除日程 |
| GET | `/api/settings` | 读取设置 |
| PUT | `/api/settings` | 更新设置 |
| GET | `/api/events` | **SSE** 事件流 |

**SSE 事件类型**：
```
event: remind
data: {"kind":"schedule|assignment","id":123,"title":"小组会议","at":"2026-09-12T14:00:00"}

event: sync_done
data: {"added":3,"updated":5,"at":"2026-09-12T10:00:00"}

event: login_changed
data: {"state":"ok|need_login|failed"}

event: error
data: {"code":"offline|parse_error|...","message":"..."}
```

### 6.6 Electron 外壳

- **窗口**：`frame:false, transparent:true, alwaysOnTop:true, skipTaskbar:true`；启动时定位到屏幕右下角附近，记忆上次位置。
- **拖动**：前端顶栏设置 `-webkit-app-region: drag`。
- **进程管理**：主进程启动时 spawn `backend.exe`，退出时结束子进程；后端崩溃则自动重启并提示。
- **托盘**：右键菜单 —— 显示/隐藏、立即同步、设置、退出；左键点击切换显隐。
- **通知**：可选调用 `new Notification()` 发系统通知（与前端气泡二选一或并存，由设置控制）。
- **自启**：可选写入注册表 Run 项（或 `auto-launch` 类库）。

### 6.7 Web 前端

- **结构**：
  - 无边框圆角窗口，半透明毛玻璃背景。
  - 月视图日历：今日高亮；有事项的日期显示小圆点 / 色块。
  - 点击日期 → 展开当日事项列表（自建日程可编辑；BB 作业带 `[BB]` 标记且只读）。
  - 添加 / 编辑日程弹层：标题、开始/结束时间、全天开关、备注、预警时间、颜色。
  - 设置面板：账号登录、刷新频率、BB 全局预警规则、提醒形式、开机自启、窗口置顶、透明度。
  - 提醒气泡：无边框小卡片，含标题 + 时间，按钮「稍后提醒」「知道了」。
- **状态管理**：轻量，直接操作 DOM + 少量模块化；日历数据经 `/api/calendar` 获取并本地缓存。

## 7. 数据模型（SQLite DDL）

```sql
-- 自建日程
CREATE TABLE schedule (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  title        TEXT    NOT NULL,
  note         TEXT,
  start_at     TEXT    NOT NULL,      -- ISO8601 本地时间
  end_at       TEXT,
  all_day      INTEGER NOT NULL DEFAULT 0,
  remind_before INTEGER,              -- 提前秒数（NULL = 不提醒）
  color        TEXT,
  created_at   TEXT,
  updated_at   TEXT
);

-- 从 BB 拉取的作业（只读缓存）
CREATE TABLE assignment (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  course_id    TEXT NOT NULL,
  course_name  TEXT,
  content_id   TEXT NOT NULL,
  title        TEXT NOT NULL,
  due_at       TEXT,                  -- ISO8601 本地时间（由 BB 的 UTC 转换）
  submitted    INTEGER,               -- 0/1
  status       TEXT,
  score        REAL,
  possible     REAL,
  synced_at    TEXT,
  UNIQUE(course_id, content_id)
);

-- 设置
CREATE TABLE setting (
  key   TEXT PRIMARY KEY,
  value TEXT
);

-- 已触发的提醒记录（防止重复推送，日程与作业统一走此表）
CREATE TABLE reminder_log (
  kind       TEXT    NOT NULL,      -- 'schedule' | 'assignment'
  ref_id     INTEGER NOT NULL,      -- schedule.id 或 assignment.id
  offset_sec INTEGER NOT NULL,      -- 提前秒数
  fired_at   TEXT    NOT NULL,
  UNIQUE(kind, ref_id, offset_sec)
);

CREATE INDEX idx_schedule_start ON schedule(start_at);
CREATE INDEX idx_assignment_due ON assignment(due_at);
```

## 8. 数据流

**启动时序**
```
Electron 启动 → 创建窗口(显示加载态) → spawn backend.exe
  → 后端读 DPAPI 凭据
      ├─ 有凭据 → 静默 CAS 登录 → 拉 BB 作业 → 写库
      └─ 无凭据 → 上报 need_login
  → 前端 GET /api/state + /api/calendar 渲染 → 建立 SSE 连接
```

**定时**
- 每 `refresh_interval_min`（默认 30）分钟同步一次 BB。
- 提醒线程每 30 秒检查一次。
- SSE 心跳保活；前端断线自动重连。

**提醒**
```
候选命中 → 写入 reminder_log → SSE 推送 remind → 前端弹气泡
                                            └→ (可选) 系统通知
```

## 10. 错误处理与降级

| 场景 | 处理 |
|---|---|
| 未登录 / 无凭据 | 显示内嵌登录卡片 |
| 密码错误 | 提示重输；DPAPI 凭据保留但标记失效 |
| 校外网络不可达 | 顶部状态条提示「可能不在校园网/VPN」；展示上次缓存并标注同步时间 |
| 会话 401 | 自动重登一次；失败转手动登录 |
| 单课程接口异常 | 不影响其它课程；记日志 |
| 后端崩溃 | Electron 自动重启后端并提示 |
| 睡眠唤醒漏提醒 | 唤醒后补检查并补发 |
| BB 字段结构变更 | 解析失败 → 报 `parse_error`，保留旧缓存，提示「接口可能需要更新」 |

## 11. 配置项（`%APPDATA%\作业日程\config.json`）

| 键 | 默认 | 说明 |
|---|---|---|
| `refresh_interval_min` | 30 | BB 同步间隔（分钟） |
| `bb_remind_defaults` | `[1440, 120]` | BB 作业全局预警（提前分钟；1 天 + 2 小时） |
| `bb_remind_enabled` | true | 是否对 BB 作业提醒 |
| `remind_popup` | `inapp` | `inapp` / `toast` / `both` |
| `always_on_top` | true | 窗口置顶 |
| `opacity` | 0.95 | 窗口透明度 |
| `autostart` | false | 开机自启 |

## 12. 打包与部署

- 后端：`pyinstaller --onefile backend.py` → `backend.exe`。
- 前端：构建为静态文件，随后端一起托管（亦可内嵌进 exe）。
- 外壳：`electron-builder` → NSIS 安装包 / 便携版。
- 体积预估：Electron 壳 ~150MB + 后端 ~40MB。
- 分发：单机自用，无需自动更新。

## 14. 风险与开放问题

| # | 风险 / 问题 | 说明与应对 |
|---|---|---|
| 1 | BB 无官方接口契约 | 字段可能变更；参考项目即靠逆向。解析层需容错，失败保留旧缓存 |
| 2 | 学期 ID 探测 | 策略需实测：优先不带 termId；否则动态探测 + 缓存 |

| 6 | DPAPI 换机 | 加密数据绑定用户账户，换机/重装需重新登录保存凭据 |
