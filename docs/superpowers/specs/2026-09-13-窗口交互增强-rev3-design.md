## 2. 现状与约束

**窗口（`electron/main.js`）**
- `BrowserWindow` 408×760、`useContentSize`、无边框、`transparent`、`resizable:false`、`maximizable:false`、`skipTaskbar:true`、`hasShadow:false`、`alwaysOnTop` 可配置。
- 位置记忆：`window_pos`（`moved` 事件防抖 500ms → `PUT /api/settings`）。
- 现有 IPC：`shell:set-always-on-top`、`shell:set-opacity`（含 0.3–1 钳制）、`shell:set-autostart`、`shell:get-autostart`、`shell:notify`、`shell:open-external`。

**设置面板（`frontend/`）**
- 「窗口」组：置顶开关、透明度**数字输入**（0.3–1.0 step 0.05）、开机自启开关；`保存` 统一 `PUT`，并对 `hwShell` 调用做 `Promise.allSettled`。
- 标题栏操作区目前仅「设置」⚙ 一个按钮。

**持久化（`backend/config.py`）**
- `load_config()`：以 `DEFAULT_CONFIG` 为底、叠加存储值。
- ⚠️ `save_config()` **只持久化 `DEFAULT_CONFIG` 中已存在的键**（`if k in DEFAULT_CONFIG`）——新增 `window_size` 键**必须同步加入 `DEFAULT_CONFIG`**，否则写入即被丢弃（本设计已计入 T2 范围）。

**约束**
- 内容布局自适应（100vw/100vh）；缩放按 408×760 等比进行（40%–150%），应用时按当前显示器工作区钳制。
- 收起态**不跨会话保留**（重启回正常窗口，避免"窗口消失"）。
- 单实例 + 托盘常驻语义不变。

## 3. 方案设计

### 3.1 N1 透明度滑块 + 实时反馈

- UI：`<input id="s-opacity" type="range" min="0.3" max="1" step="0.05">` + 读数 `<span id="s-opacity-val">95%</span>`（替代现有数字输入）。
- 实时：`input` 事件（拖动中，节流 ~50ms）→ `hwShell.setOpacity(v)`（主进程即时生效）→ 窗口透明度实时变化；读数同步更新。
- 持久化：`change` 事件（松手）→ `PUT /api/settings {opacity}` 写穿（无需等「保存」）；「保存」按钮仍统一提交其余设置。
- 降级：无 `hwShell`（纯浏览器调试）仅更新读数、不报错。
- 主进程 `shell:set-opacity` 已带钳制，沿用不改。

### 3.2 N2 窗口大小（已决策：等比缩放滑块，40%–150%）

- UI：「窗口」组新增「窗口缩放」滑块：`<input id="s-scale" type="range" min="40" max="150" step="5">` + 读数 `100%（408×760）`（读数随拖动实时更新）。
- 生效：`change`（松手）→ `hwShell.setWindowScale(p)` → 主进程按 `round(408×p/100) × round(760×p/100)` `setContentSize`，并按当前显示器**工作区钳制**（超限时等比回缩，窗口位置一并修正到完整可见）。
- 持久化：`window_scale`（整数百分比）写入配置（`DEFAULT_CONFIG` 新增键）；启动时应用。
- 基准：现有 `WINDOW_WIDTH/HEIGHT`（408×760）常量。
- 取舍：40% ≈ 163×304，低比例下设置弹层与日列表会明显拥挤、可读性下降——按用户要求保留该范围；T4 走查对 40% / 100% / 150% 三档截图评估，必要时再迭代。

### 3.3 N3 贴边收起（"小边边"）

- **收起入口**（已决策：仅标题栏）：标题栏操作区新增按钮「▸」`#btn-edge-hide`（tooltip「收起至屏幕右侧」，调用 `hideToEdge()`）。
- **收起形态**：主窗口先记忆 **content bounds** 再 `hide()`；在原显示器**右缘**创建小窗「边缘条」：**16×120**、透明无边框、`alwaysOnTop`、`skipTaskbar`、`resizable:false`；因 Windows 对 frameless 窗口有最小宽度约束，采用 `type:"toolbar"` + 构造后 `setBounds`（实测唯一可达 16×120 的组合）；视觉为竖条填满窗口（圆角 + 悬停高亮；「微放大」因窗宽裁剪放弃）。内联 `data:` URL 页面绘制（不新增打包文件）。
- **唤出**：点击边缘条（获得焦点）→ 主窗口按记忆 content bounds `show()` + 聚焦（复原时按当前工作区钳制）；边缘条销毁。收起态下再次启动应用（`second-instance`）视同唤出。
- **细节**：
  - 显示器取 `screen.getDisplayMatching(主窗口前 bounds)`；边缘条垂直中心 = 主窗口垂直中心（钳制在工作区）。
  - 收起态下托盘「显示/隐藏」= 唤出。
  - 多显示器跟随；DPI 由 Electron 统一换算。
  - 应用退出时随进程销毁，无残留。

## 6. 验收标准

1. 回归：backend 118 + frontend（21+新增）全绿；`node --check` 通过。
2. **N1**：拖动滑块窗口透明度实时变化；松手后**重启应用**仍为设定值；无 `hwShell` 环境不报错。
3. **N2**：滑块 40%–150% 可调（100% 为标准）；松手即生效、重启保留；尺寸不超出当前显示器工作区；40% / 100% / 150% 三档截图供评估（低比例可读性下降为已知取舍）。
4. **N3**：点击收起入口 → 窗口消失、屏幕右缘出现小条；点击小条 → 完整窗口按原位置恢复；连续 3 次稳定；应用退出后无残留小窗。
5. 测试隔离 + 进程/端口零残留 + 无凭据落盘。

## 7. 风险与边界

- 边缘条可能被全屏应用遮挡：置顶可缓解；不做全局热键（超出本轮范围）。
- 低比例（<60%）下界面可读性下降：按用户要求保留 40% 下限，T4 走查评估后再决定是否优化。
- 透明窗口 + 多显示器/DPI：以 `screen` 工作区坐标为准 + 真机验证。
- `window_scale` 越界脏值：加载时钳制到允许范围。

## 8. 实测记录（T4 真机走查与修复轮）

> 环境：Windows 11 + 150% DPI（2560×1600）、Electron 44.3.0；用户实例为真实数据；隔离验证用独立 `--user-data-dir` + `APPDATA`；凭据未写入任何文件。

### 8.1 走查结果（对照 §6）

- **N1 透明度**：滑块 0.3–1.0（step 0.05）+ 读数；拖动中节流 IPC 实时改窗，松手写穿 `PUT {opacity}`；实测 1.0 → 0.5 即时生效并落盘、重开一致；无 `hwShell` 环境降级不报错。
- **N2 窗口缩放**：40% → 实测 164×304（标称 163×304，±1 DIP 舍入）；150% → 574×1068（标称 612×1140，被工作区等比钳制；松手后读数回填实际值）；100% → 408×760；`window_scale` 落盘、**重启生效**（含位置钳制落盘）。
- **N3 贴边收起**：标题栏「▸」→ 主窗隐藏（OS `IsWindowVisible=False`）、右缘竖条 **16×120**（@150% 物理 24×180）；**真实鼠标点击**竖条 → 完整窗口按原 content bounds 恢复（连续 2 轮，几何差 0px、`pages` 回 1）；截图 + 视觉复核（浅蓝圆角竖条、无残影）；重启不保留收起态。
- 走查后用户原设置已还原（`opacity=1`、`window_scale=100`）。
