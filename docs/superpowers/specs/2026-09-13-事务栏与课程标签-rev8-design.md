# 作业日程 — 日列表事务栏与课程彩色标签设计（rev8）

## 1. 需求拆解

| # | 要求 | 目标定义 |
|---|---|---|
| R1 | BB 行双倍行高 | 常规行基线 `min-height: 33px`（= 自然高，视觉零变化）；`.bb-row` `min-height: 66px`（= 2×33） |
| R2 | 课程彩色标签 | BB 行两行结构：第 1 行 = 时间 + 彩色 chip（chip 只在第 1 行）；第 2 行 = 单行省略标题；移除「BB」文字徽标（其 tooltip 信息迁至 chip） |
| R3 | 颜色分散且稳定 | 色相取「已占用色相」集合上的最大空隙中点；同课程 hue 恒定并持久化；文字色按真实相对亮度取对比更高一侧 |
| R4 | 零回归 | 点击/hover/分页（每页 ≤3）/自建日程行外观/窗口自适应/缩放全部不变；后端与 Electron 不改动 |

## 2. 现状与约束

- 现状渲染（`app.js::renderDay`）：`title.textContent = 「【课程名】标题」`，BB 行另附 `.tag`「BB」徽标；行高由内容决定（单行 33px）。
- 课程名来源：`assignment.course_name`（DB 由 BB 同步写入，可空）；同课程无稳定 id 之外的键，`course_id` 存在于数据中但与展示解耦。
- 约束：前端零构建、零依赖、ES Modules；外部字符串一律 `textContent`；纯逻辑放 `frontend/lib/` 以便 `node --test` 覆盖。
- 视觉约束：chip 单行省略（绝不换行），否则 BB 行会突破 2× 高度；无 `course_name` 的 BB 行不渲染 chip，标题垂直居中但高度仍 66px（= 2×33）。

## 3. 方案设计

### 3.1 布局与尺寸（R1/R2）

```
.day-list li.bb-row（min-height:66px = 2×33, align-items:flex-start, padding 11px/8px）
┌──────────────────────────────────────────────┐
│ [时间]  [● 课程彩色 chip]                     │ ← 第 1 行：时间与 chip 顶对齐
│         作业标题……（单行省略）                │ ← 第 2 行：item-title（flex:1;min-width:0）
└──────────────────────────────────────────────┘
```

- `.day-list li { min-height: 33px }`：常规行基线 = 自然高（padding 6/6 + 行高 21px），视觉零变化；**2× 关系以该值为准**（改 padding/字号需同步两个值）。
- `.day-list li.bb-row { min-height: 66px; align-items: flex-start; padding-top/bottom: 11px }`：chip(19) + gap(3) + 标题(21) = 43px 内容，上下 11px 使其在 66px 内居中（实测 chip 顶距 11px / 标题底距 12px）。
- `.bb-main { display:flex; flex-direction:column; gap:3px; flex:1; min-width:0 }`：右侧纵向容器；`.bb-main .item-title { flex:1; min-width:0 }` 保证省略号生效。
- `.course-chip { display:inline-block; align-self:flex-start; max-width:100%; padding:1px 8px; border-radius:7px; font-size:11px; font-weight:600; line-height:17px; white-space:nowrap; overflow:hidden; text-overflow:ellipsis }`（chip 高 19px，`align-self` 防止在列内被拉伸）。
- 无课程名：`li.bb-row.no-chip`（`align-items:center` + 恢复 6px padding），标题直接作为 li 子元素居中，高度仍 66px。
- 时间与 chip 对齐依据：两者同为 flex 子项、顶对齐；12px 时间行盒（18px）与 19px chip 的中心差 ≈0.5px。
- chip tooltip：`chip.title = 课程名 + (submitted ? " · 已提交" : "")`，承接原「BB」徽标信息，并顺带提供长名全文。

### 3.2 课程配色算法（`frontend/lib/colors.js`，纯模块）（R3）

- `hueForName(name, takenHues)`：把已占用色相**先归一化到 [0,360) 再去重**（`-30` 与 `330` 视为同一色相）、丢弃非有限值，排序后在**环形相邻对**中找最大空隙，取其中点；空集返回 210（默认蓝）；单元素取对侧；并列空隙取下限一侧（严格 `>` 比较，确定性）。`name` 暂不参与计算（参数保留），避免名字散列带来的重色风险。
- `hslColor(hue)` = `hsl(hue, 72%, 52%)`（鲜艳、固定 S/L 保证风格统一）。
- `contrastText(hue)`：把同一 HSL 换算为 sRGB → WCAG 相对亮度 → `> 0.2241` 用 `#1f2937`、否则 `#ffffff`。0.2241 为「深字/白字对比度相等点」：`L(#1f2937)=0.02153`，由 `(L+0.05)² = 1.05×(0.02153+0.05)` 反解；即每个色相都取对比更高的一侧（实测深字区间 ≈15°–210°，1° 级边界；默认蓝 210° 深字 3.85:1 略高于白字 3.81:1，故取深字）。
- `assignHues(assigned, names)`：对未分配名字**按码点排序**逐个取最大空隙中点，返回**无原型对象**（`Object.create(null)`，避免 `__proto__` 等特殊键被赋值吞掉）；不修改入参；已分配项跳过。
- 分配结果（5 门课的隔离实测）：`大学物理（下）210 / 思想道德与法治 30 / 数据结构与算法 120 / 线性代数 300 / 计算机科学与工程系专业导论 75`；相邻环距最小 45°。

### 3.3 持久化与稳定性（`app.js` + `backend/config.py`）（R3）

- **存储介质：后端配置 `config.json` 的 `course_hues` 键**（`DEFAULT_CONFIG` 新增 `"course_hues": {}`，dict：课程名 → 色相）。
  - 为什么不用 localStorage：后端端口每次启动随机（`config.py "port": 0` → 运行时选定），渲染页 origin 随之变化 → localStorage 按 origin 隔离，**重启必然丢失并全量重算**（首版实现即踩此坑，本轮修复）。
- `state.courseHues: Map<课程名, hue>`；`init()` 先 `await refreshSettings()`（GET `/api/settings`）再加载月/日数据，`hydrateCourseHues()` 把配置值并入内存表（仅接受有限数字、已有键不改色）→ **chip 首帧即用持久化色相**，无"先算后换"闪烁。
- `syncCourseHues()` 在 `loadMonth()`/`loadDay()` 末尾、渲染之前调用：取 `monthData.assignments ∪ dayData.assignments` 的课程名 → `assignHues()` → **仅当有新名字**时写内存并 `scheduleHueSave()`。
- `scheduleHueSave()`：**防抖 400ms** 后 `PUT /api/settings { course_hues }`——只提交这一个键，后端 `update_config` 为 patch 合并语义（`save_config` 键过滤 + `load→update→save` 持锁），不覆盖窗口位置/缩放等其他设置；失败仅保留内存态（pending 不落），下次变化再调度重试。
- **已分配课程永不改色**：只增量补齐，不做覆写；重名/空名跳过。
- 渲染兜底：`const hue = state.courseHues.get(name) ?? hueForName(name, [...values()])`——不变量：渲染前必经 `syncCourseHues` 补齐（loadMonth/loadDay 末尾），此 `??` 仅防御异常路径（配置读取失败后直接渲染），只算内存色、不落盘。
- **保证与例外**：保证 = 跨重启/跨导航/端口变化恒定（已分配课程永不改色）；例外 = 课程改名按新名重新分配、清空应用数据（config.json）后按新数据集重排、已消失课程的条目保留不清理（仍占色相名额）。

### 3.4 不变项

- 点击 → `openItemOverview`；hover 背景；每页 3 条与分页器；自建日程行（时间+标题+可选左侧色条）。
- `fitHeight` 上报时机不变（chip 行高变化经既有 ResizeObserver/`reportFit` 自适应窗口）。
- 后端 `db.py`、Electron `main.js/preload.js` 零改动。

## 6. 风险与边界

- **长课程名**：chip 以省略号截断（tooltip 提供全文）；不换行是把 BB 行锁在 2× 高度的前提。
- **色相分配是「首次出现顺序 + 名称排序」确定性**：清空应用数据（localStorage）会按新顺序重排颜色；同一份数据内恒定。
- **课程改名**（course_name 变化）会得到新颜色（以名字为键的取舍）；`course_id` 更稳定但与展示解耦，留作后续可选增强。
- **深/浅底文字色**：按 WCAG 相对亮度取对比更高侧；L=52% 的鲜艳底色对白字仍在 3.8:1 一档（如蓝 210/品红 300），低于小字号 4.5:1 的理想值，但符合需求「鲜艳」约束，属已知取舍。
- 行高 2× 以**常规行自然高 33px** 为基线（不是 padding 数值）：若未来改常规行 padding/字号，需同步 `.bb-row` 的 `min-height`（两处已加注释互指）。
- 70% 档下 chip 字号 11px → 物理约 8px，仍可读但偏小；MIN_ZOOM=0.7 为既有下限，不属本轮改动范围。
